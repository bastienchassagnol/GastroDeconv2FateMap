# Contributing to DeCovarT

Thank you for your interest in contributing to **DeCovarT** — a covariance-aware bulk transcriptome deconvolution package.
DeCovarT implements the first deconvolution algorithm that explicitly accounts for gene–gene interactions through cell-type-specific covariance structures.
Contributions that extend, benchmark, or improve the methodology are warmly welcome.

## Fixing typos and documentation errors

Small typos or grammatical errors in documentation should be edited in the _source_ file, not the auto-generated one:

- **YES:** edit a roxygen2 comment in a `.R` file under `R/`.
- **NO:** edit an `.Rd` file under `man/` (these are auto-generated by `roxygen2::roxygenise()`).

## Reporting bugs

If you have found a bug, please [open an issue](https://github.com/bastienchassagnol/DeCovarT/issues) and include:

- A minimal reproducible example ([reprex](https://www.tidyverse.org/help/#reprex)) using the bundled datasets (`bivariate_configuration`, `bivariate_parameters`) where possible.
- The output of `sessionInfo()`.
- The exact error message or unexpected behaviour observed.

## Proposing new features

Before opening a pull request for a substantial change, please file an issue first so that the scope and scientific validity of the proposal can be discussed.
Areas where contributions are especially welcome include:

- **New deconvolution algorithms** implementing the standard interface expected by `deconvolute_ratios()` (i.e. a function accepting `y`, `mean_signature_matrix`, optionally `Sigma`, and `true_ratios`).
- **New regulatory network estimation strategies** to refine the structure of the precision matrix.
- **Extended benchmarking scenarios** beyond the bivariate toy example, e.g. higher-dimensional GRN-based simulations using `simulate_hierarchical_grn_moments()`.
- **Performance improvements** to the Marquardt–Levenberg optimiser or its gradient/Hessian computations.

## Pull request process

1. Create a dedicated Git branch for each pull request (`git checkout -b feat/my-feature`).
2. Follow the [Air](https://posit-dev.github.io/air/) formatter conventions configured in `air.toml` at the project root for consistent code style.
3. Document all user-facing functions with [roxygen2](https://cran.r-project.org/package=roxygen2) using Markdown syntax, including `@param`, `@return`, and at least one `@examples` entry.
4. Add or update [testthat](https://cran.r-project.org/package=testthat) tests under `tests/testthat/`. Contributions with test coverage are much easier to review and accept.
5. Run `devtools::check()` and ensure there are no `ERROR` or `WARNING` messages before submitting.
6. For user-facing changes, add a bullet point to the top of `NEWS.md` (below the current development version header) describing what changed, followed by your GitHub username and links to the relevant issue(s) or PR(s).
